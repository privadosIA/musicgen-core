# musicgen-core

Model-agnostic building blocks shared by the C#/TorchSharp ports of music-generation models
(HeartMuLa.Net, DiffRhythm2.Net): safetensors reading and writing, strict checkpoint loading, rotary embeddings,
norms, convolution layers, window assembly, WAV writing and the test helpers for parity tests.

## Contents (namespaces `MusicGen.Core.*`)

| Namespace | Types |
|---|---|
| `Weights` | `SafeTensors`, `CheckpointIndex`, `SafeTensorsWriter`, `StrictLoader`, `WeightNorm` |
| `Layers` | `RmsNorm`, `FlowRmsNorm`, `RotaryEmbedding`, `FlowAttention`, `FlowMlp`, `Conv1dLayer`, `ConvTranspose1dLayer`, `PReLULayer` |
| `Audio` | `WavWriter`, `WindowAssembler` |
| `Text` | `PythonText` (+ tables generated by `tools/gen_python_text_data.py`) |
| `MusicGen.Core` | `Seeding` |
| `MusicGen.Core.Testing` | `Parity`, `FixtureDirectory` (SHA-256 verified against `MANIFEST.md`), `CheckpointEnvironment` and the `Requires*FactAttribute` bases, `Bf16`, `Rng`, `WavFile` |

Parameter names of every layer are the checkpoint keys (`scale`, `weight`, `bias`, `q_proj.weight`, …), and a test lists them.

## Things that look alike and are not interchangeable

- **RMSNorm**: `RmsNorm` is torchtune's (parameter `scale`, computed in float32 and cast back); `FlowRmsNorm` is HeartCodec's (parameter `weight`,
  computed in the input dtype). HuggingFace's `LlamaRMSNorm` (`weight`, float32) is a third flavor that is not here yet.
- **RoPE**: `RotaryEmbedding` has no default layout. `RopeLayout.AdjacentPairs` rotates `(x[2i], x[2i+1])` (torchtune); `HalfRotation` rotates
  `(x[i], x[i + d/2])` (HuggingFace `rotate_half`, checked against a fixture generated from `transformers`). `RopeFrequencies.Plain` or
  `Llama3Scaled`; `RopeTable.Float32Cached` (float32 table, rotation in float32) or `InputDtypePerCall` (everything in the input dtype). With bf16
  inputs `HalfRotation` + `Float32Cached` is not bit-equal to HuggingFace, which multiplies in the activation dtype; they agree for float32.
- **Seeding**: TorchSharp's `torch.manual_seed` seeds only the CPU generator; use `Seeding.Apply` (also seeds CUDA). See
  `docs/torchsharp-findings.md` for the evidence.
- **Solution builds**: a consumer that does not list these projects in its solution must keep `ShouldUnsetParentConfigurationAndPlatform=false`
  (set in this repository's `Directory.Build.props` and, for the consumer's own projects, in theirs); otherwise `-c Release` compiles the core in Debug.

## Layout

- `src/MusicGen.Core` — the library.
- `src/MusicGen.Core.Testing` — helpers for consumers' tests (references xunit; the library does not).
- `tests/MusicGen.Core.Tests` — the core's own tests.
- `docs/torchsharp-findings.md` — TorchSharp behavior that differs from PyTorch.

## Build and test

```
dotnet build -p:TorchBackend=cpu        # cpu | cuda-windows | cuda-linux
dotnet test  -p:TorchBackend=cpu
```

## Consuming it

Consumers reference `$(MusicGenCoreDir)/src/MusicGen.Core/MusicGen.Core.csproj`; `MusicGenCoreDir` defaults to the sibling
folder `../musicgen-core` and can be overridden with `-p:MusicGenCoreDir=...`. Core and consumer must use the same
`TorchSharpVersion` in their `Directory.Build.props`.

## CI

`.github/workflows/ci.yml` builds and tests `MusicGen.Core.sln` with the CPU backend. A consumer's CI checks this repository out next to its own
(see HeartMuLa.Net's README, "Shared core and CI") and builds against the exact commit it checked out.
